# Standard library

[Documentation](index.mdx)

Std lives at root `std/`. Canonical modules include `std.core`, `std.collections`, `std.text`,
`std.io`, `std.fs`, `std.net.socket`, and `std.net.http`. Operational failures use checked errors,
absence uses `Option`, and success-only operations return `void`.

## Text and collections

Lengths, capacities, and indices use `i64` and `length()`. String capacity excludes its terminator.
`String` owns bytes; `StringView` borrows bounded bytes. View-based operations preserve embedded zeros.
`String` and `Vector<T>` copy deeply; boxes and resource handles are move-only.

Vectors destroy removed elements and move initialized values during growth. Invalid public sizes
and overflow use checked errors. Maps store key/value pairs in one vector with linear lookup.
Use `String(cstr)` for copies and `String::from(number)` for conversion. Float conversion may throw
`ConversionError`. `Memory::move(box).into_inner()` extracts a boxed value; raw adoption/transfer
uses `from_raw`/`into_raw`.

## Output

```zep
import std.io.FormatArguments
import std.io.print

var mut arguments = FormatArguments()
arguments.add(42)
print("value: {}\n", arguments)
```

`print`/`eprint` return void and suppress write errors. Plain calls print braces literally;
formatted calls take explicit owned `FormatArguments`, falling back to the original pattern if
formatting fails. `format` is checked and returns `String`; `{}` consumes arguments and doubled
braces escape them. Use checked `StandardFile::write` for confirmed delivery. Text accepts `cstr`,
`String`, and `StringView`. Panic stays allocation-free and low-level.

## Resources and HTTP

`File`, `Directory`, sockets, and pipes use small RAII owners. Explicit close reports errors;
destructors handle failures locally. File writes handle partial writes and interrupted operations.
Byte reads and process capture preserve binary data. Nonzero process exits are results, while
start/read/wait failures throw. Error structs retain operation and native error information.

HTTP clients and servers use `handle(Method, ...)`. Clients take an explicit IPv4 address separately
from the Host header. Server handlers are borrowed interface values whose owners must outlive the
server. Routes are ordered; a trailing `*` matches a prefix. Missing routes return 404 and unsupported
methods return 405. `serve_one()` serves once; `serve()` loops.

HTTP supports fragmented input, connection-close responses, and Content-Length. Header/body limits
are 64 KiB/8 MiB. DNS, TLS, chunked transfer, persistent connections, and concurrency are unsupported.
See the [notes example](../examples/notes/README.md).
