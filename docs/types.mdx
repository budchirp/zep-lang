# Types

[Documentation](index.mdx)

| Types | Meaning |
|---|---|
| `void`, `never` | No value; no normal return |
| `boolean`, `char`, `cstr` | Boolean, C character, C string |
| `i8`, `i16`, `i32`, `i64` | Signed integers |
| `u8`, `u16`, `u32`, `u64` | Unsigned integers |
| `f32`, `f64` | Floating-point numbers |
| `any` | Opt out of strict compatibility |
| `*T`, `*mut T` | Immutable/mutable raw pointers |
| `&T`, `&mut T`, `move T` | Borrowed and move references |
| `T[N]`, `T[]` | Fixed and unsized arrays |
| `(T1, T2) -> R` | Function/closure |
| `@throws(E) (T) -> R` | Checked-error callback |
| `Name<T>`, `Outer::Inner` | Generic and nested types |

## Compatibility

Integer literals default to `i32`, floats to `f64`; expected numeric types provide context.
Already-typed numbers do not implicitly widen. Use `as` for explicit conversion.
Arrays require matching shapes and compatible elements. Nonempty literals infer from their
first element; empty arrays need an expected type.

Mutable pointers convert to immutable pointers, not the reverse. Void pointers accept compatible
qualifiers but require explicit casts back to typed pointers. Array pointers can decay one dimension.
C-string conversion requires suitable byte storage and caller-provided zero termination.

Derived values/pointers may convert to bases; by-value conversion slices. Interface conversion
requires a declared implementation. Callback signatures include their checked-error sets.
`any`, null, and `never` participate in special compatibility rules; they do not establish valid storage.

Primitive facades add methods without changing representation: `Integer`, `Float`, `Boolean`,
`Char`, and `CStr`. Examples include `32.to_string()` and `"zep".to_string()`; `.value` exposes
the primitive. See [generics](generics.mdx) and [references](memory.mdx).
